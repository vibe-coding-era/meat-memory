# Memory的能力

**1. 短期记忆：上下文窗口管理**

管理当前对话/任务中的即时信息：

- 保留当前用户意图、约束、偏好、正在处理的文件/分支/任务状态
- 识别哪些上下文是“现在必须用的”，哪些只是背景噪音
- 在上下文窗口接近上限时做局部压缩
- 避免把过期结论、旧计划、误解继续带入后续推理
- 在中断、恢复、compact 后尽量保持任务连续性

**2. 中期记忆：项目临时记忆与工作文档**

管理一段时间内对项目有用、但未必需要永久保存的信息：

- 记录当前项目目标、阶段性决策、临时约定
- 保存正在推进的任务状态、待办、风险点、验证结果
- 记录代码库结构、关键模块关系、调试线索
- 支持按项目、分支、任务、时间范围检索
- 允许把临时记忆升级为长期知识，或在完成后归档/删除

**3. 长期记忆：知识库与可复用经验**

沉淀跨会话、跨任务、跨项目仍有价值的信息：

- 保存用户偏好、协作习惯、项目背景、架构原则
- 保存稳定的事实、领域知识、设计决策、踩坑经验
- 支持基于 scope / project / topic 的长期检索
- 让 Agent 在新会话里能“接上这个人和这个项目”
- 区分事实、推测、偏好、历史记录、行动建议，避免混成一团

**4. 理解：从信息到语义结构**

不只是存文本，而是理解文本代表什么：

- 识别用户意图、任务目标、约束、优先级
- 抽取实体：项目、模块、文件、人物、会议、需求、决策
- 判断信息类型：事实、偏好、计划、问题、结论、经验
- 建立“这条记忆为什么重要、什么时候会被用到”的语义标签
- 识别冲突、重复、过期、模糊信息

**5. 压缩：把复杂上下文变成可用摘要**

让记忆更小、更稳定、更容易召回：

- 对对话、代码探索、会议内容、任务过程进行摘要
- 保留决策、原因、约束、未完成事项，而不是机械截断
- 生成不同粒度的摘要：一句话、任务级、项目级、知识级
- 对多轮相似内容去重和合并
- 在压缩时保留可追溯来源，避免“压缩后失真”

**6. 关联：让记忆之间形成网络**

记忆不只是列表，而是能互相连接：

- 把需求与代码模块、PR、bug、会议、决策关联起来
- 把用户偏好和具体行为样例关联起来
- 把相似问题、历史修复、复用方案连接起来
- 支持“这件事和之前哪件事有关”的召回
- 形成项目知识图谱或轻量关系网：人、事、物、时间、因果

**7. 遗忘：主动清理和降低权重**

好的记忆系统必须会忘：

- 删除明确错误、敏感、临时、用户要求遗忘的信息
- 对过期信息降权，而不是永远同等重要
- 对任务完成后的临时上下文做归档或清理
- 区分“硬删除”和“保留历史但不主动召回”
- 避免旧偏好、旧架构、旧计划污染当前判断

**8. 演进：记忆随项目变化而更新**

项目和用户都会变，记忆也要变：

- 当新事实出现时更新旧记忆，而不是简单追加
- 记录决策从 A 变成 B 的原因
- 维护版本化的项目认知：过去怎样、现在怎样、为什么变了
- 从多次任务中抽象出更稳定的模式
- 支持“这条记忆是否仍然成立”的再验证

**9. 召回：在正确时机拿出正确记忆**

记忆能力最终要体现在使用上：

- 根据当前任务自动检索相关项目背景
- 根据用户表达召回偏好和历史约定
- 根据代码位置召回相关架构/踩坑/测试方法
- 控制召回量，避免把一堆不相关历史塞回上下文
- 能解释“为什么这条记忆被召回”

**10. 治理：可控、可审计、可纠错**

让用户能信任记忆系统：

- 用户可以查看、修改、删除记忆
- 每条重要记忆有来源、时间、作用范围、置信度
- 敏感信息有权限和边界
- 系统能标记推断内容，不把推断伪装成事实
- 支持项目级、用户级、全局级作用域隔离

我会把这套能力粗分成一句话：短期记忆负责“不断线”，中期记忆负责“项目不断片”，长期记忆负责“知识不白费”；而理解、压缩、关联、遗忘、演进，是让这三层记忆从“存储”变成“智能协作能力”的关键。
