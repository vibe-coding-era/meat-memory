# V2.91 Compatibility Contract

## 1. 老版本行为兼容

| 入口 | V2.91 承诺 |
|---|---|
| `remember_text` | 保持旧 title/body/kind/source_refs/visibility/sensitivity 语义 |
| `search_context` | 保持 scope、query、limit、recall guard、markdown fallback 默认行为 |
| `get_memory` | 保持 PG 优先、Markdown fallback 的读取语义 |
| lifecycle | 保持 V2.7 inspect/status/forget/restore 行为 |
| proposal / rollback / profile / distill | 保持 V2.8 命令、核心 payload 和治理状态流转 |

## 2. 接口兼容

| Surface | V2.91 规则 |
|---|---|
| CLI | 只新增 `benchmark` 子命令，不改旧子命令名称和参数 |
| HTTP | V2.91 不新增 HTTP benchmark route，避免提前冻结未完成 API |
| MCP | V2.91 不新增 MCP benchmark tool，后续 V2.95 做 surface parity |
| Markdown | 旧 scope `MEMORY.md` projection 可继续解析 |
| PG | 旧表不删除、不改名、不收窄字段约束 |

## 3. Schema 兼容

`0009_memory_v2_91_benchmark.sql` 只新增以下对象：

- `benchmark_suites`
- `benchmark_runs`
- `benchmark_case_results`
- benchmark run / failure 查询索引

迁移要求：

- 可重复执行：使用 `CREATE TABLE IF NOT EXISTS` 和 `CREATE INDEX IF NOT EXISTS`。
- 可跳过新能力：旧业务路径不依赖 benchmark 表。
- 可回滚入口：停用 benchmark CLI 即可，不影响 V2.7 / V2.8 主链路。

## 4. 对手功能兼容

| 竞品心智 | V2.91 兼容方式 |
|---|---|
| Supermemory container / project memory | 用 benchmark scope 和 suite 元数据对齐，不复制其 API |
| mem0 add/search/delete 基准 | `meat-code-zh` 使用 remember/search 链路作为本地可比口径 |
| MemoryLake provenance / passport | V2.91 仅保留 report path 和 case result，passport 在 V2.94 承接 |

## 5. 不兼容边界

- V2.91 不承诺 LoCoMo / LongMemEval / BEAM 完整数据格式。
- V2.91 不承诺竞品 API 级兼容。
- V2.91 不把 benchmark 数据写入用户默认 scope，默认使用 `scp_benchmark_meat_code_zh` 或显式 `--scope-id`。
