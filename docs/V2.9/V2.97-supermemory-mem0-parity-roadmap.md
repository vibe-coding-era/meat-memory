# V2.97 Supermemory / mem0 实际功能对比与追平路线图

状态：Development In Progress

更新时间：2026-04-28

## 1. 定位

V2.97 不再只做“竞品心智映射”，而是基于实际可调用功能重新对比 Meat Memory V2.9、Supermemory 和 mem0，并给出追平到超越的完整功能路线图。

本方案不从已有 V2.9 文档反推结论。V2.9 侧只按当前代码中已经存在的 CLI / HTTP / MCP / Kernel 能力计入；Supermemory 和 mem0 侧按公开产品、API、SDK、OSS 仓库可验证能力计入。

## 2. 当前实际功能对比

| 维度 | Meat Memory V2.9 实装能力 | Supermemory 实际能力 | mem0 实际能力 | 当前判断 |
|---|---|---|---|---|
| 基础写入 | `remember`、`remember-image`、docs import、本地 markdown / PG 写入 | text / URL / file / video ingest，自动抽取 memory | add / update / delete memory，SDK 和 API 成熟 | Supermemory / mem0 更成熟 |
| 检索 | `search`，并有 recall trace、budget pack、failure explain | search、hybrid search、rerank / rewrite、profile + search results | semantic search、advanced filters、pagination | Supermemory 检索体验更强；V2.9 可解释性更强 |
| 图谱 / 关系 | entities / relations / timeline / context bundle，尚未产品化成 graph memory | memory graph 心智存在，但公开控制面有限 | Graph Memory 明确、可接 graph backend、关系召回更成熟 | mem0 更强 |
| 多租户 / 身份建模 | `scope_id`、visibility、access key、agent context | container tag、user/project 分区 | user / agent / app / run / org / project 维度完整 | mem0 更完整 |
| Connectors | local-git、markdown-docs、chat-export skeleton | Notion、Google Drive、OneDrive、web crawler 等连接器 | 公开能力里 connectors 不是主打 | Supermemory 明显领先 |
| Profile / 个性化 | distillation profile 有基础，但还不是产品化 user profile | profile 能力更直观，可与 search 一起返回 | memory types / entities，有 profile 心智但不如 Supermemory 明显 | Supermemory 领先 |
| 生命周期治理 | lifecycle status、forget / restore、proposal、review、rollback、audit | 有 create / forget / search，但治理链不完整 | CRUD / history / export，但治理闭环不如 V2.9 | V2.9 领先 |
| 可解释性 | benchmark、trace inspect、health report、failure classification | 搜索与处理链路有结果，但缺少同级 trace explain 产品面 | 有 API / events，但缺少同级 recall trace | V2.9 领先 |
| 可移植性 | Memory Passport export / verify / import / provenance | 未见同级可验证 passport bundle | 有 export，但不是 manifest/hash 驱动 passport | V2.9 领先 |
| 本地优先 / 自托管 | markdown-first，可选 PG，CLI / HTTP / MCP 都可本地跑 | 更偏托管 API / Router / MCP 服务 | OSS / self-host 能力成熟 | V2.9 与 mem0 领先 |
| Agent 接入 | CLI / HTTP / MCP 三端都有，MCP 偏安全只读 | API、MCP、Memory Router 接入体验顺 | REST API、SDK、OSS server、webhook | Supermemory / mem0 更顺手 |
| 观测 / 质量门禁 | benchmark、health、trace、coverage gate | 未见同级内建 QA 面 | 有 benchmark 资产，但不在核心产品面 | V2.9 领先 |

## 4. 差距归纳

| 差距 | 对标对象 | 影响 | V2.97 目标 |
|---|---|---|---|
| Connectors 仍是 skeleton | Supermemory | 用户不能一键导入真实工作空间数据 | 做成可运行 sync engine |
| Graph Memory 未产品化 | mem0 | 关系召回、实体合并、关系解释不够强 | 做实体 / 关系 store、graph search 和关系解释 |
| user / agent / app / run / org 维度不足 | mem0 | 多 Agent、多应用场景接入成本高 | 建立 Memory Namespace API |
| Profile / Memory Router 不够顺 | Supermemory | 开发者接入需要显式改工作流 | 提供 router / profile 一体入口 |
| 多模态 ingest 不完整 | Supermemory | 音频、视频、网页能力弱 | 补 ASR、视频关键帧、网页抓取和 evidence |
| SDK 生态不足 | Supermemory / mem0 | 开发者采用成本高 | TypeScript / Python SDK 与 examples |
| 导入兼容只是 fixture | Supermemory / mem0 | 迁移仍需要手工适配 | 做真实 import adapter 和 dry-run report |
| 性能与大规模数据验证不足 | mem0 / Supermemory | 10K / 100K / 1M 级场景说服力不够 | 建立规模压测和指标趋势 |

## 5. 最全功能路线图

### P0：追平接入与数据入口

| 功能 | 对标 | 交付标准 |
|---|---|---|
| Notion connector | Supermemory | 支持 workspace/page/database 读取、增量 sync、source refs、dry-run |
| Google Drive connector | Supermemory | 支持 docs / sheets / PDFs metadata 和文本抽取 |
| OneDrive connector | Supermemory | 支持文件枚举、hash 去重、增量同步 |
| Web crawler connector | Supermemory | 支持 URL ingest、robots / allowlist、网页正文抽取、canonical URL |
| Local Git connector 实装 | Supermemory | 支持 repo metadata、commit log、README/docs、重要文件索引 |
| Markdown docs connector 实装 | Supermemory | 支持目录扫描、frontmatter、文档变更检测、evidence span |
| Chat export connector 实装 | Supermemory / mem0 | 支持 ChatGPT / Claude / Slack / Lark export 格式归一化 |
| mem0 import adapter | mem0 | 支持 user_id、agent_id、app_id、run_id、metadata、memory type 映射 |
| Supermemory import adapter | Supermemory | 支持 containers、documents、chunks、URLs、metadata 映射 |

### P1：追平 Graph Memory 与 Namespace

| 功能 | 对标 | 交付标准 |
|---|---|---|
| Memory Namespace API | mem0 | 支持 user / agent / app / run / org / project 显式建模 |
| Graph Memory store | mem0 | 实体、关系、关系权重、关系来源可持久化 |

| Graph search | mem0 | search 可同时返回 memory、entity、relation、path explanation |

### P2：追平 Profile / Router / SDK 体验

## 7. 验收门槛

- 每个 connector 必须支持 dry-run、增量 sync、source refs、failure report。
- 每个 import adapter 必须支持 dry-run、scope mapping、id mapping、validation error report。
- Graph Memory 必须在 search payload 中返回 relation path explanation。
- SDK 必须覆盖 CLI / HTTP / MCP 已有核心能力，不允许只包装 remember/search。
- 多模态 ingest 必须输出 evidence span，而不是只保存 caption 文本。
- 所有新增生产代码继续要求 targeted coverage 100%。
- V2.97 必须提供真实功能 demo，不再只接受 mapping fixture。

## 8. 建议优先级

第一优先级是 Connectors MVP 和 import adapter，因为这是 Supermemory 的最大现实优势，也是用户迁移的第一道门。第二优先级是 Namespace + Graph Memory，因为这是 mem0 的最大现实优势。第三优先级是 Profile + Router + SDK，它决定开发者是否愿意长期接入。最后再做多模态和超越项，把 V2.9 已经领先的 trace、health、passport 变成更强的产品体验。
