# V2.93 Secret Guard 与 Health Report 开发方案

状态：Implemented

更新时间：2026-04-27

## 1. 目标

V2.93 把安全风险和记忆健康风险纳入主链路：写入时检测并处理 secret / PII，召回时再次阻断未脱敏 secret，health report 输出可审计的风险列表和建议动作。

## 2. 范围

- 新增 `SecretFinding`、`MemoryHealthRisk` 等领域对象。
- 新增 secret / PII detector，覆盖 API key、Bearer token、private key、password、email、phone、private path。
- 写入链路支持 `allow`、`redact`、`proposal`、`deny` 动作。
- 召回链路增加 secret recall guard，阻断未脱敏高风险内容。
- hard delete / deleted 状态变更时清理高风险正文并保留最小审计。
- Health Report 输出重复、冲突、过期、低置信度、高敏感、无人审阅、缺证据、secret finding 风险。
- 新增 CLI `memory-cli health report`，写入 JSON / Markdown 投影。
- 新增 PG `0011` 迁移保存 `secret_findings` 和 health report 元数据表。
- 新增 security / health observability metrics。

## 3. 兼容策略

- 旧 `remember` / `search` / `lifecycle report` 命令保持可用，新增字段只追加。
- 迁移只做 additive tables，不修改 V2.7 / V2.8 / V2.91 / V2.92 旧表语义。
- Markdown memory projection 继续使用旧格式；health report 写入独立 `tests/reports/health/latest/`。
- 已脱敏标记如 `[REDACTED:API_KEY]` 可被 health 识别，但不会被 recall guard 当作原始 secret 阻断。
- Health Report 只输出建议动作，不自动执行 merge、archive、redact 或 hard delete。

## 5. 验收

`docs/scripts/v2_93-acceptance.sh` 覆盖：

- domain / kernel / CLI / observability / PG migration 单测。
- API key 写入自动脱敏。
- private key 写入被拒绝。
- search 不泄漏原始 API key。
- health report 输出 secret finding、高敏感风险和建议动作。
- V2.93 新增生产代码 100% 覆盖率口径说明。

## 6. 后续边界

V2.93 不做复杂 ML/LLM secret detector，不自动执行 high-risk proposal，也不默认 hard delete；这些能力继续通过 V2.8 proposal / review 和后续 V2.94 passport redaction 承接。
