# V2.91 Acceptance

## 1. 必须通过

| 验收项 | 标准 |
|---|---|
| CLI benchmark | `memory-cli benchmark run --suite meat-code-zh` 可生成报告 |
| 报告完整性 | `summary.md`、`metrics.json`、`failures.jsonl`、`latency.jsonl`、`leakage.jsonl` 存在 |
| 指标完整性 | 报告包含 recall@1、recall@5、latency、leakage、failure reason |
| 兼容回归 | V2.7 lifecycle smoke 和 V2.8 governance smoke 通过 |
| 覆盖率 | V2.91 新增生产代码 line / function / region coverage 目标为 100% |

## 2. 推荐命令

```bash
./docs/scripts/v2_91-acceptance.sh
```

## 3. 报告位置

```text
tests/reports/benchmark/latest/
  summary.md
  metrics.json
  failures.jsonl
  latency.jsonl
  leakage.jsonl
  benchmark-run.json
  coverage-v2_91-new-code.md
  v2_91-acceptance.txt
```

## 4. 覆盖率说明

V2.91 的 100% 覆盖率先以新增生产代码的直接测试覆盖为门禁：

- 每个新增 domain 类型和 metric 函数有单测。
- 每个 benchmark runner 分支有 kernel 测试。
- 每个 CLI benchmark 输出和报告读取分支有测试。
- 新迁移文件由 PG storage contract test 引用校验。

后续 V2.96 汇总发布时，再把 V2.91 到 V2.96 的覆盖率报告统一纳入 `v2_9-coverage-threshold.py`。

## 5. 失败处理

| 失败 | 处理 |
|---|---|
| recall 低于预期 | 先查看 `failures.jsonl`，确认 fixture 词项和 search 排序 |
| latency 异常 | 查看 `latency.jsonl`，确认是否 PG / Markdown 混用 |
| leakage 非 0 | 查看 `leakage.jsonl`，确认 restricted memory 是否进入 recall guard |
| V2.7 / V2.8 smoke 失败 | 停止推进 V2.92，先修兼容回归 |
