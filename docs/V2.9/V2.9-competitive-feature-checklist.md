# V2.9 超越竞品功能清单

状态：Planning Draft

更新时间：2026-04-22

## 1. 目标定位

V2.9 的目标是在不依赖 SaaS 化的前提下，把 Meat Memory 推进为：

> 最可信、最可控、最会治理、最懂项目演进的 Agent Memory Kernel。

本清单面向 Supermemory、mem0、MemoryLake 三类竞品能力，重点补齐可证明、可治理、可解释、可迁移和多模态能力。

## 2. 功能清单

| 优先级 | 功能 | 对标对象 | 验收标准 |
|---|---|---|---|
| P0 | LoCoMo / LongMemEval / BEAM 官方评测接入 | mem0 / MemoryLake / Supermemory | 仓库内可一键跑 benchmark，输出准确率、token 成本、延迟、失败样例 |
| P0 | 中文 + 代码项目专用 MemoryBench | 全部 | 建立中文、代码、Agent 任务基准，覆盖项目决策、约束、历史 bug、评审偏好 |
| P0 | Proposal-first 记忆治理 | MemoryLake | 新记忆进入 duplicate / merge / supersede / conflict / unrelated 判定，不盲目追加 |
| P0 | 版本时间线与 rollback | MemoryLake | 每条关键记忆可查看历史、diff、来源，并可恢复到旧版本 |
| P0 | Recall Explanation | 全部 | 每次召回说明为什么召回、匹配了什么、来自哪个 scope、置信度多少、为什么过滤其他内容 |
| P0 | Recall Budget Packer | Supermemory / mem0 | 在固定 token budget 下自动选择 summary / full / evidence，避免上下文超预算 |
| P0 | Secret / PII / 凭证检测 | 全部 | API key、token、隐私路径、敏感正文默认不长期保存或自动脱敏 |

| P1 | 项目身份识别 | 全部 | 能稳定判断这是同一个 repo、项目或工作集，避免同项目被分裂成多个 memory scope |

## 3. 杀手级能力

| 能力 | 说明 |
|---|---|
| 可解释召回 | 竞品能搜到，我们要能解释为什么搜到、为什么没有搜到 |
| 用户参与式治理 | 从 append-first 走向 proposal / review / version / rollback |
| 项目认知网络 | 记住项目、任务、决策、风险、历史 bug 的演进关系 |
| 本地优先 + 可迁移 | memory 能本地运行、审计、导出、迁移、恢复 |
| 公开 benchmark 反超 | 用 LoCoMo、LongMemEval、中文代码任务基准证明能力提升 |

## 4. 建议路线

| 阶段 | 目标 |
|---|---|
| 1 | 补 benchmark + recall explanation，让能力差距可量化 |
| 2 | 完成 V2.8 proposal / version / rollback，建立 MemoryLake 级治理能力 |
| 3 | 做 recall budget、项目身份识别、memory 关系网络，追平并超过 Supermemory 的上下文能力 |
| 4 | 做音频、视频、evidence，全多模态追平 |
| 5 | 做 Browser Console、Memory Passport、Health Report，形成可见产品优势 |

## 5. 完成定义

V2.9 可以视为具备超越竞品的非 SaaS 核心竞争力，当以下条件满足：

- 至少一个公开 benchmark suite 可一键运行并生成稳定报告。
- Recall Explanation 能覆盖检索命中、过滤和预算裁剪原因。
- Proposal-first 治理闭环覆盖 duplicate、merge、supersede、conflict。
- 关键记忆支持版本时间线、rollback、forget、restore 和审计。
- 项目身份识别和 memory 关系网络能服务真实代码项目场景。
- 多模态 evidence 至少覆盖文本、图片、音频三个来源。
- Browser Console 能展示 proposal queue、timeline、recall explanation 和 health report。

## 6. 竞品对比备注

本节用于记录制定 V2.9 清单时参考的竞品差距。评分为 10 分制，权重为：功能 25%、架构 20%、性能 15%、安全治理 20%、用户体验 / 生态 10%、可控部署 10%。

| 产品 | 功能覆盖 | 技术架构 | 性能 / 规模 | 安全治理 | UX / 生态 | 可控部署 | 加权总分 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Supermemory | 9.2 | 8.5 | 8.7 | 8.2 | 9.2 | 8.3 | 8.7 |
| MemoryLake | 8.5 | 8.4 | 8.6 | 9.5 | 8.1 | 7.8 | 8.6 |
| mem0 | 7.8 | 8.7 | 8.4 | 8.6 | 8.2 | 9.0 | 8.4 |
| Meat Memory | 7.2 | 8.3 | 6.8 | 7.2 | 7.4 | 9.0 | 7.6 |

| 维度 | Supermemory | mem0 | MemoryLake | Meat Memory 当前状态 |
|---|---|---|---|---|
| 核心定位 | 全栈 context infra：memory、RAG、profiles、extractors、connectors、plugins | 开发者优先的 AI memory layer，托管 + OSS | Memory Passport + 企业知识库 + 强安全追溯 | 自托管 Agent 长期记忆内核，强调 scope、治理、CLI / HTTP / MCP |
| 功能强项 | 用户画像、memory graph、文档 RAG、多模态、连接器、跨工具记忆 | 快速接入、user / session / org memory、OSS、自选向量库和 LLM | 版本、来源、冲突、审计、安全、知识库项目组织 | PG + Markdown + Assets、文本 / 图片、scope promotion、lifecycle、recall guard、MCP / CLI / HTTP |
| 技术架构 | 托管图谱引擎 + Memory Router + hybrid retrieval | LLM 抽取 + vector / entity / SQL，多信号检索，开源架构清晰 | D1 engine、git-like versioning、provenance、安全优先 | Rust workspace 分层清晰，kernel / policy / sync / store / http / mcp 解耦 |
| 性能依据 | 官方称 p95 <300ms，LongMemEval / LoCoMo / ConvoMem 表现强 | 官方新算法 LoCoMo / LongMemEval 分数高，BEAM 覆盖 1M / 10M tokens | 官方 LoCoMo repo 称 overall 94.03% | 本地 perf smoke 很快，但缺公开 LoCoMo / LongMemEval / 大规模压测 |
| 安全治理 | OAuth / API key、scoped key、SOC2 / HIPAA / GDPR、自托管 / VPC | user / agent 隔离、SOC2 / HIPAA / BYOK、OSS 自控 | 三方加密、E2E、ISO27001、SOC2 Type II、GDPR / CCPA，最强 | access key、visibility / sensitivity、restricted recall guard、安全回归；无认证证书 / E2E |
| 用户体验 | 个人 app、Chrome extension、Claude / Cursor / OpenClaw 插件，最完整 | 开发者体验强，终端用户体验依赖集成方 | Passport / 项目知识库体验好，开发生态相对少 | CLI / TUI / Browser Console / Agent skills 可用，但还不是 polished SaaS |
| 主要短板 | 闭源核心较多，benchmark 口径需谨慎核对 | 文档 RAG / 连接器不是主战场，高级能力平台和 OSS 有差异 | 开发生态和公开复现资料相对少，部分功能口径偏产品叙事 | 缺音频 / 视频、连接器、公开 benchmark、商业合规认证、完整 UI |
| 最适合 | 做通用 AI agent context stack | 给应用快速嵌入长期记忆 | 高安全 / 审计 / 来源追踪场景 | 本地 / 私有化 Agent 记忆内核、可控部署、工程内嵌 |

结论：Meat Memory 当前不是输在架构，而是输在公开 benchmark、连接器、多模态覆盖、商业合规认证和产品化 UI。V2.9 应优先补可证明能力和治理闭环，再补多模态 evidence、Browser Console 与 Memory Passport。
