# V2.7 生产质量门禁

状态：Implemented

更新时间：2026-04-21

## 1. 目标

V2.7 已进入可商用生产底座阶段，质量门禁的目标不是证明“能跑”，而是防止以下问题进入生产：

- 中文、多字节文本路径出现 panic。
- 记忆来源元数据丢失，导致召回解释和治理失真。
- restricted 记忆在授权场景不可用，或在未授权场景泄漏。
- migration、Markdown projection、HTTP/MCP/CLI 接入面漂移。
- 安全专项、中文语料、生命周期治理回归被遗漏。

## 2. 门禁入口

本地快速门禁：

```bash
./docs/scripts/v2_7-production-gate.sh
```

发布前严格门禁：

```bash
V2_7_GATE_STRICT=1 V2_7_GATE_COVERAGE=1 ./docs/scripts/v2_7-production-gate.sh
```

严格门禁要求本地 PostgreSQL 可达，默认地址为 `127.0.0.1:5433`。如需覆盖：

```bash
V2_7_GATE_PG_ADDR=127.0.0.1 V2_7_GATE_PG_PORT=5433 ./docs/scripts/v2_7-production-gate.sh
```

## 3. 门禁矩阵

| 门禁项 | 命令 | 目的 |
|---|---|---|
| 格式检查 | `cargo fmt --all --check` | 防止低质量 diff 进入主线 |
| 接口一致性 | `cargo check --workspace --all-targets` | 捕获 feature/API/测试目标编译漂移 |
| P1 生命周期回归 | `cargo test -p memory-kernel --lib lifecycle -- --test-threads=1` | 固定中文截断、source metadata、restricted 授权召回 |
| Kernel 集成流 | `cargo test -p memory-kernel --test kernel_flow_tests -- --test-threads=1` | 覆盖 remember/search/lifecycle 主链路 |
| 存储和迁移单测 | `cargo test -p memory-store-pg --lib -- --test-threads=1` | 覆盖 PG schema、audit、source_refs 兼容 |
| Markdown roundtrip | `cargo test -p memory-store-md --lib -- --test-threads=1` | 防止 projection/frontmatter/parser 丢字段 |
| HTTP/MCP/CLI 接入面 | `cargo test -p memory-http -p memory-mcp -p memory-cli -- --test-threads=1` | 防止入口漂移和参数不一致 |
| 安全专项 | `SECURITY_REPORT_WRITE=0 ./docs/scripts/security-report.sh` | 覆盖敏感路由、MCP auth、payload boundary |
| V2.7 全验收 | `./docs/scripts/v2_7-acceptance.sh` | 在 PG 可用时跑完整 lifecycle acceptance |
| 覆盖率阈值 | `docs/scripts/v2_7-coverage-threshold.py` | 对指定主入口/集成文件执行 95% 阈值检查 |

## 4. 覆盖率策略

生产门禁采用两层覆盖率策略：

- 必须达标：`main.rs`、`lifecycle_impl.rs` 的 line/function/region 都必须不低于 95%。
- 继续推进：`app.rs`、HTTP/MCP/PG 大集成文件继续通过 seam 拆分提升覆盖率，不用脆弱测试硬凑数字。

覆盖率检查默认关闭，因为生成覆盖率需要额外 profile 产物。发布前打开：

```bash
V2_7_GATE_COVERAGE=1 \
V2_7_GATE_COVERAGE_REPORT=target/coverage/v2_7-production/report.txt \
./docs/scripts/v2_7-production-gate.sh
```

覆盖率报告必须包含阈值脚本检查的所有文件行。不要用只包含 CLI 的局部 report 作为生产覆盖率输入。

## 5. 本地与发布前差异

| 模式 | PostgreSQL 不可用 | 适用场景 |
|---|---|---|
| 默认本地门禁 | 跳过完整 V2.7 acceptance，只跑 no-PG 稳定套件 | 日常开发、快速自检 |
| 严格生产门禁 | 直接失败 | release 前、商用部署前、合并主干前 |

## 6. 当前 P1 回归已固定

当前 lifecycle 回归测试覆盖：

- `compact_summary_handles_long_chinese_text_without_panic`
- `normalizer_preserves_source_ref_and_kind_for_long_term_records`
- `recall_guard_filters_restricted_memories_by_request_context`

这些测试是 V2.7 商用门禁的一部分，不应被跳过或降级。
