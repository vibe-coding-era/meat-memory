# V2.7.1 现有能力与目标能力差距分析

状态：Planning Draft

更新时间：2026-04-17

## 1. 分析原则

本文件只把“已经有领域模型、Kernel 主链路、接口或测试证明”的能力算作现状能力。

不把 V3 planning 文档中的目标能力误算为已实现能力。

## 2. 当前能力总判断

当前 `Meat Memory` 最准确的状态不是“长期记忆系统”，而是：

一个已经具备三层记忆骨架，但还没有形成统一生命周期闭环的记忆内核。

## 3. 能力对比表

| 能力域 | 目标能力 | 当前状态 | 现状说明 | 核心缺口 |
|---|---|---|---|---|
| 短期记忆 | 会话不断线、任务上下文、压缩与恢复 | partial | 已有 `AgentContext` 的 upsert/list/promote/delete 主链路 | 缺自动压缩、过期处理、恢复策略 |
| 中期记忆 | 项目临时记忆、工作文档、任务阶段上下文 | partial | 已有 `ProjectDocument`、`MemorySource`、本地 docs sync、冲突报告 | 缺统一的任务状态、阶段决策、风险和验证结果模型 |
| 长期记忆 | 稳定知识沉淀、跨会话复用 | strong | `Memory` + remember/search/publish/promote 已可用 | 缺更新、遗忘、审计、解释的闭环 |
| 理解 | 分类、重要性判断、事实边界识别 | partial | 已有 entity / relation 抽取和基础 score 字段 | 缺完整 type/source/confidence/status 管线 |
| 压缩 | 任务摘要、项目摘要、多粒度摘要 | weak | 仅有 `summary` kind 和少量 summary 字段 | 缺真正的 compression service |
| 关联 | 图谱、记忆间关系、项目认知网络 | partial | 已有 entity / relation / context bundle | 缺 memory-to-memory 关系、timeline、supersede |
| 遗忘 | soft forget、hard delete、排除召回 | weak | 状态枚举有 archived/deleted/conflicted | 缺 forget service、audit、recall guard |
| 演进 | 新事实更新旧记忆、冲突与替代 | weak | 有 `deprecated/conflicted/published_from_scope_id` 等苗头 | 缺 conflict detector、version event、supersede flow |
| 召回 | 任务感知召回、预算控制、召回解释 | partial | 已有 search/fetch_context 和混合检索基线 | 缺 recall intent、budget packer、explanation |
| 治理 | 查看、修改、删除、审计、隔离 | partial | 已有 scope、visibility、sensitivity、key policy | 缺 memory 级 CRUD、审计日志、治理报告 |

## 4. 最关键的结构性事实

### 4.1 已经存在三层记忆骨架

| 层 | 当前对象 | 当前角色 |
|---|---|---|
| 短期 | `AgentContext` | 当前 session/task 的实时上下文 |
| 中期 | `ProjectDocument`、`MemorySource` | 项目工作集、文档集、同步来源 |
| 长期 | `Memory` | 跨会话长期沉淀知识 |

### 4.2 缺的是统一生命周期，不是更多入口

当前系统已经有：

- CLI
- HTTP
- MCP
- Skill

所以 V2.7 的重点不应该是新增更多外壳，而应该是补：

- schema
- lifecycle
- recall explanation
- governance
- audit

## 5. 当前能力的产品风险

### 5.1 文档真相分裂

当前仓库存在两个偏差：

- 一部分文档仍把系统描述成“长期记忆库”
- 另一部分规划已经按“理解、压缩、召回、演进、治理”在设计

这会导致团队对系统成熟度判断失真。

### 5.2 能力碎片化

`AgentContext`、`ProjectDocument`、`Memory` 各自可用，但没有统一归口：

- 写入语义不统一
- 生命周期不统一
- 召回语义不统一
- 治理能力不统一

### 5.3 用户信任不足

当前系统虽然能记住和检索，但对以下问题回答还不够好：

- 为什么记住这条
- 为什么召回这条
- 为什么不召回那条
- 这条记忆是否过期
- 这条记忆是否已被替代

## 6. V2.7 设计原则

### 6.1 复用优先

V2.7 必须复用当前对象和链路：

- 不重写 `AgentContext`
- 不重写 `ProjectDocument`
- 不重写 `Memory`

### 6.2 先把“骨架”变成“系统”

先统一：

- 数据模型
- 生命周期
- 召回逻辑
- 治理逻辑

再做更重的智能能力。

### 6.3 保守自动化

V2.7 不默认自动覆盖、不自动删除、不自动把推断伪装成事实。

自动化优先做：

- 分类
- 摘要
- 排序
- 风险标记

而不是高风险写回。

## 7. 本阶段建议

V2.7 最应该优先补的不是复杂模型能力，而是以下四件事：

1. 统一 schema
2. 统一 recall guard
3. 统一 governance 与 audit
4. 统一 memory-to-memory 演进关系

只要这四层立住，后续无论是多模态还是更强理解模型，都可以逐步接进来，而不必推倒重来。
