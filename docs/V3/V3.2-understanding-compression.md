# Meat Memory V3.2 理解与压缩

状态：Planning Draft

更新时间：2026-04-13

## 1. 版本目标

V3.2 在 V3.1 的结构化记忆基础上，建立理解与压缩管线，把原始对话、任务过程、文件内容、会议内容转化为高质量记忆。

一句话目标：提升写入质量，避免长期记忆变成原始文本垃圾堆。

## 2. 产品方案

### 2.1 用户故事

| 角色 | 用户故事 | 价值 |
|---|---|---|
| 用户 | 我希望系统能自动识别哪些内容值得记，哪些只是临时噪音 | 减少手工整理 |
| Agent | 我希望把长任务压缩成保留目标、约束、决策、原因、待办的摘要 | 减少上下文浪费 |
| 项目维护者 | 我希望重复或相似记忆能被合并，而不是不断追加 | 保持知识库干净 |
| 审阅者 | 我希望系统区分事实、推测、偏好、计划 | 降低长期误导 |

### 2.2 核心场景

| 场景 | 行为 |
|---|---|
| 长对话结束 | 生成 task summary，抽取决策、问题、待办、经验 |
| 用户明确说“记住” | 标记为 explicit，提高写入优先级 |
| Agent 推断出结论 | 标记为 inferred 或 unverified，不伪装成事实 |
| 重复内容写入 | 发现近似记忆，合并或跳过 |
| 项目阶段性总结 | 生成 project summary，为后续召回提供短摘要 |

### 2.3 功能分解

| 功能 | 说明 | 优先级 |
|---|---|---|
| 记忆分类器 | 判断候选内容属于 fact、decision、issue 等类型 | P0 |
| 重要性判断 | 判断是否值得写入中期/长期记忆 | P0 |
| 任务摘要生成 | 任务结束后生成结构化摘要 | P0 |
| 多粒度摘要 | 支持 session、task、project 摘要 | P1 |
| 去重合并 | 避免重复记忆污染库 | P1 |
| 事实边界标记 | 区分 explicit、inferred、unverified | P1 |
| 摘要保真评估 | 检查是否遗漏决策、约束、原因链 | P2 |

## 3. 技术方案

### 3.1 理解管线

```text
raw text
  -> normalize
  -> classify memory candidates
  -> score importance
  -> compress each candidate
  -> infer confidence
  -> dedupe
  -> write/update
```

### 3.2 服务模块

| 模块 | 职责 |
|---|---|
| `MemoryUnderstandingService` | 从原始输入中抽取候选记忆 |
| `MemoryClassifier` | 对候选记忆进行类型分类 |
| `ImportanceScorer` | 评估稳定性、复用价值、用户显式性、项目相关性、时效性 |
| `CompressionService` | 生成 summary 和可选 dense_summary |
| `DedupeService` | 基于 hash、embedding、scope/type/content 相似度去重 |
| `WritePolicy` | 决定不写入、写 session、写 project 或写 long-term |

### 3.3 分类与打分策略

| 维度 | 说明 |
|---|---|
| 稳定性 | 是否预计在未来仍成立 |
| 复用价值 | 是否会影响后续任务 |
| 用户显式性 | 用户是否明确要求记住 |
| 项目相关性 | 是否绑定当前项目或 scope |
| 时效性 | 是长期事实还是短期状态 |
| 风险 | 是否包含敏感信息或不可靠推断 |

建议先使用规则 + LLM 的混合策略：明确触发词、scope、状态由规则处理，复杂语义分类再交给模型。

### 3.4 摘要模板

任务摘要建议保留：

| 字段 | 说明 |
|---|---|
| `goal` | 本次任务目标 |
| `constraints` | 用户约束和工程约束 |
| `decisions` | 已确认的设计或实现决策 |
| `changes` | 完成的变更 |
| `open_questions` | 未解决问题 |
| `next_steps` | 后续动作 |
| `evidence` | 来源或引用 |

### 3.5 去重策略

| 策略 | 说明 |
|---|---|
| Exact hash | 对完全相同内容直接跳过 |
| Near duplicate | 同 scope + 同 type + 高相似度时合并 |
| Superset merge | 新记忆包含旧记忆时更新摘要或 metadata |
| Conflict defer | 语义相反时不合并，交给 V3.4 冲突检测 |

## 5. 验收标准

| 标准 | 说明 |
|---|---|
| 候选抽取 | 给定任务对话，能抽取多个结构化候选记忆 |
| 类型分类 | 候选记忆能被分类到合理 type |
| 摘要保真 | 摘要保留目标、约束、决策、原因、待办 |
| 去重有效 | 重复内容不会无限追加 |
| 事实边界 | 推断内容不会被标记成 explicit fact |
