# Meat Memory V3.5 遗忘、治理与用户控制

状态：Planning Draft

更新时间：2026-04-13

## 1. 版本目标

V3.5 为长期运行的记忆系统补齐可控、可审计、可维护能力，避免记忆越存越乱、越存越危险。

一句话目标：让记忆系统长期可信可控。

## 2. 产品方案

### 2.1 用户故事

| 角色 | 用户故事 | 价值 |
|---|---|---|
| 用户 | 我希望能明确要求系统遗忘某些信息 | 保持控制权 |
| 安全负责人 | 我希望敏感信息不会被长期保存或主动召回 | 降低隐私和合规风险 |
| 项目维护者 | 我希望过期、低置信度、被替代的记忆能被归档或降权 | 保持记忆库健康 |
| Agent | 我希望查询前有统一 recall guard，避免误用 forgotten 或敏感信息 | 降低行为风险 |

### 2.2 核心场景

| 场景 | 行为 |
|---|---|
| 用户要求遗忘 | 默认 soft forget，从召回中排除并保留审计 |
| 用户强要求删除 | 对指定记忆执行 hard delete |
| 检测到敏感信息 | 默认不长期保存，或写入前脱敏 |
| 临时任务结束 | task/session 级记忆归档或设置过期 |
| 健康检查 | 输出冲突项、过期项、重复项、敏感风险 |

### 2.3 功能分解

| 功能 | 说明 | 优先级 |
|---|---|---|
| 用户显式遗忘 | 按 id、scope、type、tag、时间范围遗忘 | P0 |
| Recall 排除 | forgotten、敏感、过期内容不主动召回 | P0 |
| 敏感信息检测 | token、key、邮箱、手机号、凭证、私密路径 | P0 |
| 审计日志 | 记录 write/update/recall/archive/delete/forget | P1 |
| 生命周期维护 | 扫描 expires_at、低置信度、长期未召回记忆 | P1 |
| 批量治理 | 按 scope、时间、类型批量归档或清理 | P1 |
| 治理报告 | 记忆数量、热点、过期项、冲突项、敏感风险 | P2 |

## 3. 技术方案

### 3.1 遗忘策略

| 策略 | 说明 |
|---|---|
| Soft Forget | 默认 `status=forgotten`，从召回中排除，保留审计 |
| Hard Delete | 对敏感信息或用户强要求执行物理删除 |
| Archive | 对任务完成或不再活跃的信息设置 `status=archived` |
| Deprecate | 对被替代的旧知识设置 `status=deprecated` |
| Needs Review | 对冲突或低置信度信息设置 `status=needs_review` |

治理流程：

```text
active memory
  -> stale detected
  -> mark needs_review or archived
  -> if superseded, mark deprecated
  -> if user forgets, mark forgotten
  -> if sensitive, hard delete or redact
```

### 3.2 服务模块

| 模块 | 职责 |
|---|---|
| `ForgetService` | 执行 soft forget / hard delete |
| `PrivacyGuard` | 检测和处理敏感信息 |
| `AuditLogService` | 记录所有关键操作 |
| `LifecycleMaintenanceJob` | 定期归档、降权、标记 review |
| `GovernanceService` | 批量治理入口 |
| `MemoryHealthReporter` | 生成健康报告 |

### 3.3 审计日志

建议审计事件结构：

```json
{
  "id": "audit_xxx",
  "memory_id": "mem_xxx",
  "action": "forget",
  "actor": "user",
  "reason": "user_requested",
  "before": {
    "status": "active"
  },
  "after": {
    "status": "forgotten"
  },
  "created_at": "2026-04-13T00:00:00Z"
}
```

### 3.4 敏感信息策略

| 类型 | 默认行为 |
|---|---|
| API key / token / secret | 阻止长期保存或脱敏 |
| 邮箱 / 手机号 | 根据 scope 和用户确认决定是否保存 |
| 私密路径 | 默认降权，不主动召回 |
| 凭证文件内容 | 禁止长期保存 |
| 用户明确要求保存的敏感信息 | 需要显式确认并记录审计 |

### 3.5 管理入口

| 入口 | 能力 |
|---|---|
| CLI | list、filter、archive、forget、restore、report |
| HTTP API | 治理与审计接口 |
| MCP Tools | Agent 可调用的受控治理工具 |
| 管理页或 TUI | 后续可视化查看、编辑、删除、恢复 |

## 5. 验收标准

| 标准 | 说明 |
|---|---|
| 可遗忘 | 用户可按 id 遗忘指定记忆 |
| 不误召回 | forgotten、敏感、过期内容不会被主动召回 |
| 可审计 | 写入、更新、删除、召回、遗忘有审计记录 |
| 可维护 | 生命周期任务能标记过期或低置信度记忆 |
| 可报告 | 能输出 memory health report |
