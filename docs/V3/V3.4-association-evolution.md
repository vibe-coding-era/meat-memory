# Meat Memory V3.4 关联、冲突与演进

状态：Planning Draft

更新时间：2026-04-13

## 1. 版本目标

V3.4 把记忆从“列表”升级为“项目认知网络”，让系统能建立关系、发现冲突、记录演进。

一句话目标：让记忆知道彼此之间发生了什么关系。

## 2. 产品方案

### 2.1 用户故事

| 角色 | 用户故事 | 价值 |
|---|---|---|
| 项目维护者 | 我希望知道某个决策替代了哪个旧决策 | 保持项目认知更新 |
| Agent | 我希望发现新旧信息冲突时不要直接混用 | 降低执行风险 |
| 开发者 | 我希望按模块、文件、需求查看相关历史记忆 | 提高定位效率 |
| 用户 | 我希望查看项目认知如何从过去演进到现在 | 提升可解释性 |

### 2.2 核心场景

| 场景 | 行为 |
|---|---|
| 新决策替代旧决策 | 建立 `supersedes` 关系，旧记忆标记为 `deprecated` |
| 新事实与旧事实矛盾 | 建立 `conflicts_with` 关系，标记 `needs_review` |
| 记忆来自任务总结 | 建立 `derived_from` 关系 |
| 多条记忆涉及同一文件 | 建立实体或 `mentions` 关系 |
| 项目复盘 | 按时间线查看决策和架构演进 |

### 2.3 功能分解

| 功能 | 说明 | 优先级 |
|---|---|---|
| 实体抽取 | 抽取项目、模块、文件、任务、决策、人物、会议 | P0 |
| 关系模型 | related_to、depends_on、supersedes、conflicts_with、derived_from、mentions | P0 |
| 显式关联 API | 支持手动或系统写入关系 | P0 |
| 冲突检测 | 新记忆与旧记忆矛盾时标记 | P1 |
| Supersede 流程 | 新决策替代旧决策 | P1 |
| 演进记录 | 记录旧值、新值、原因、来源、操作者 | P1 |
| 关系图调试视图 | 用于检查关联质量 | P2 |

## 3. 技术方案

### 3.1 关系结构

```json
{
  "id": "rel_xxx",
  "from_memory_id": "mem_new",
  "to_memory_id": "mem_old",
  "relation_type": "supersedes",
  "confidence": "explicit",
  "source": "conversation",
  "created_at": "2026-04-13T00:00:00Z"
}
```

### 3.2 存储设计

| 表/对象 | 说明 |
|---|---|
| `memory_relations` | 记忆之间的关系边 |
| `memory_entities` | 从记忆中抽取出的实体 |
| `memory_entity_links` | 记忆和实体之间的映射 |
| `memory_versions` | 记录记忆演进和状态变更 |

### 3.3 关系类型

| 类型 | 说明 |
|---|---|
| `related_to` | 泛相关 |
| `depends_on` | 当前记忆依赖另一条记忆 |
| `supersedes` | 当前记忆替代旧记忆 |
| `conflicts_with` | 当前记忆与旧记忆冲突 |
| `derived_from` | 当前记忆来源于另一条记忆或摘要 |
| `mentions` | 当前记忆提到某实体或对象 |

### 3.4 冲突检测策略

优先检测高价值、低噪音场景：

| 场景 | 策略 |
|---|---|
| 同 scope + 同 entity + 同 type | 检查是否存在相反结论 |
| 新旧 decision | 如果新决策明确替代旧决策，走 supersede |
| fact 与 fact 不一致 | 标记 conflicts_with 和 needs_review |
| hypothesis 与 fact 不一致 | 降低 hypothesis 权重或标记 deprecated |

冲突检测初期不要自动删除旧记忆，只建立关系和状态标记。

### 3.5 演进流程

```text
new memory
  -> extract entities
  -> find related memories
  -> detect duplicate/conflict/supersede
  -> create relation
  -> update old memory status if needed
  -> append memory_versions event
```

## 5. 验收标准

| 标准 | 说明 |
|---|---|
| 关系可写 | 能创建 memory 到 memory 的关系 |
| 实体可抽取 | 能从记忆中抽取文件、模块、任务、决策等实体 |
| 冲突可标记 | 新旧事实矛盾时能建立 conflicts_with |
| 替代可追踪 | 新决策替代旧决策时旧记忆进入 deprecated |
| 时间线可查 | 能按项目或主题查看记忆演进 |
