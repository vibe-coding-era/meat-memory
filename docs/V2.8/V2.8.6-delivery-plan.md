# V2.8.6 实施路线、里程碑、测试与风险控制

状态：Accepted

更新时间：2026-04-24

## 1. 版本验收目标

V2.8 完成时，系统应满足以下结果：

- 能区分同项目、重复、可合并、替代、冲突
- 高风险变更不再静默执行，而是进入 proposal/review
- 用户能查看 timeline、versions、relations、audit
- 用户能 rollback、restore、reject 高风险治理动作
- 用户能配置 distillation profile 并进行 preview

## 2. 里程碑设计

| 里程碑 | 目标 | 结果 |
|---|---|---|
| M1 | 项目身份与内容关系判定 | binding、resolver、relationship classifier |
| M2 | Proposal 与 review queue | proposal schema、审批流、apply executor |
| M3 | 版本时间线与恢复 | version metadata、relations、timeline、rollback |
| M4 | Distillation profile 与 preview | profile model、preview、distill proposal 联动 |
| M5 | 接入面与文档收口 | HTTP/CLI/MCP 命令、使用文档、验收脚本 |

## 5. 测试策略

### 5.1 单元测试

重点覆盖：

- 项目绑定命中和歧义处理
- duplicate / supersede / conflict 分类
- review level 分配
- proposal 状态机
- rollback 行为
- profile 组合规则

### 5.2 集成测试

重点覆盖：

- same repo re-entry 命中已有绑定
- exact duplicate 自动去重
- new decision -> supersede proposal -> approved -> old deprecated
- conflicting fact -> conflict proposal -> needs_review
- forgotten memory -> restore
- rollback to prior snapshot
- distill preview -> merge proposal

### 5.3 回归测试

V2.8 必须保证：

- 不破坏 V2.7 recall guard
- 不破坏 `remember/search/fetch_context`
- 不破坏现有 lifecycle forget/restore/audit 路径

## 6. 指标与报告

建议形成三类报告：

| 报告 | 作用 |
|---|---|
| proposal report | review backlog、通过率、拒绝率 |
| timeline report | version / relation / rollback 覆盖 |
| distillation report | preview 命中率、被批准率、冲突率 |

## 7. 风险与控制

| 风险 | 说明 | 控制方式 |
|---|---|---|
| 设计过大 | proposal、version、profile 同时推进过重 | 先做 M1-M3，再做 M4 |
| 误判过多 | near duplicate / supersede 分类不稳 | 默认提案，不默认执行 |
| 表设计膨胀 | 一次性引入过多通用表 | 复用 `memory_versions` 与 lifecycle audit |
| Markdown 复杂化 | timeline/proposal 都投影到 Markdown | 明确 PG 为控制面主存 |
| Agent 越权 | MCP 直接批准高风险提案 | `required` proposal 仅用户可批 |

## 8. 文档与实现绑定要求

建议每项能力都绑定：

- 任务编号
- API surface
- 测试点
- 验收场景

避免出现“文档写了但没有进入接口和测试”的脱节。

## 9. 推荐发布策略

建议分两段发布：

### 阶段一

- M1-M3
- 重点是 proposal、timeline、rollback

### 阶段二

- M4-M5
- 重点是 distillation profile、preview 和 docs/acceptance 收口

这样可以更早拿到“用户可控治理”的主价值。

## 10. 完成判据

V2.8 可以视为完成，当且仅当：

- 高风险 merge/supersede/conflict 不再静默执行
- timeline 和 rollback 主链路可用
- proposal 审批和 apply 可审计
- distillation profile 至少支持全局 + 项目级配置和 preview
- HTTP / CLI / MCP 至少三者中的两者达到主链路可用，剩余一个不缺核心语义
