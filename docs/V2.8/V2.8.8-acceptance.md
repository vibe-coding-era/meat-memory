# V2.8 验收目标与场景

状态：Implemented

更新时间：2026-04-24

## 1. 验收目标

V2.8 验收的重点不是“多了几个接口”，而是以下闭环是否成立：

- 能识别项目边界
- 能把内容关系分成重复、替代、冲突
- 能把高风险动作转成 proposal
- 用户能批准、拒绝、回滚、恢复
- 提炼可预览、可重跑、可审计

## 2. 验收入口

已新增：

```bash
./docs/scripts/v2_8-acceptance.sh
```

当前脚本会串起：

- 定向单测
- 核心集成测试
- CLI smoke
- HTTP API smoke
- MCP tool listing / dispatch smoke

默认情况下，如果本地 PostgreSQL 不可达，脚本会完成无 PG 核心 smoke 并跳过 PG-backed runtime/surface 验收。发布或封板验收建议使用：

```bash
V2_8_ACCEPTANCE_STRICT=1 ./docs/scripts/v2_8-acceptance.sh
```

发布前完整门禁入口：

```bash
V2_8_GATE_STRICT=1 ./docs/scripts/v2_8-production-gate.sh
```

该门禁会额外覆盖格式、工作区接口检查、HTTP / CLI / MCP surface suites、安全专项回归，并在 strict 模式下强制执行 PG-backed acceptance。

## 3. 场景矩阵

| 场景 | 预期结果 |
|---|---|
| 已确认 repo 再次进入 | 直接命中已有项目绑定 |
| 同 scope 同 evidence 重复写入 | 自动去重或补证据，不产生额外 active |
| 近重复 summary 写入 | 创建 merge proposal |
| 新决策替代旧决策 | 创建 supersede proposal，批准后旧记忆 deprecated |
| 新旧事实矛盾 | 创建 conflict proposal，相关记录进入 needs_review |
| forgotten 记忆恢复 | restore 后再次可被 recall |
| 回滚到旧版本 | 新增 rollback snapshot，历史不丢失 |
| 用户配置 project profile | preview 结果受 profile 影响 |
| profile 改写后重跑 | 候选结果变化且 run 可追踪 |
| MCP 访问 required proposal | 不允许绕过用户批准直接 apply |

## 4. 覆盖项

### 4.1 Domain / Kernel

- binding resolve
- relationship classify
- proposal state machine
- relation create
- rollback
- profile compose

### 4.2 Interface

- HTTP `proposals`、`timeline`、`rollback`、`profiles`、`distill preview`
- CLI 同名命令
- MCP tools 注册与参数一致性

### 4.3 Governance

- 审批前不可执行 required proposal
- apply 后产生 version / relation / audit
- reject 后 proposal 不影响 active memory

## 5. 测试建议

### 5.1 单元测试

### 5.2 集成测试

- `remember -> proposal -> approve -> apply -> timeline`
- `remember -> conflict -> reject -> recall unaffected`
- `rollback -> versions list -> timeline`

### 5.3 端到端测试

- CLI 走完整审批流
- HTTP 查询和批准 proposal
- MCP 只能列出和建议，不能绕过 required 审批

## 6. 验收指标

| 指标 | 目标 |
|---|---|
| 项目绑定命中率 | 已确认项目的二次进入应稳定命中 |
| proposal 可解释性 | 所有 required proposal 都包含 reason 和 evidence |
| 静默高风险变更数 | 应降为 0 |
| rollback 可恢复性 | 可从历史 snapshot 恢复正文 |
| preview 可控性 | 更换 profile 后结果可重跑且差异可见 |

## 8. 验收通过条件

V2.8 验收通过至少需要满足：

- 核心定向单测通过
- 至少一条 supersede 主链路通过
- 至少一条 conflict 主链路通过
- timeline / rollback 主链路通过
- profile preview 主链路通过
- HTTP / CLI / MCP 中至少两条接入面通过完整主链路
